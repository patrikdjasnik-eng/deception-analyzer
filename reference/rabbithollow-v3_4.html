⚔
Threat Model (STRIDE-aligned)
What we assume · what we protect · what we never do
ASSUME
  • Attackers will find decoys
  • Some will pivot laterally
  • Credentials will be tested
  • C2 domains may be contacted
PROTECT
  • Production networks (hard isolation)
  • Real credentials & secrets
  • Operator identity (no leakage)
  • Forensic integrity of captures
NEVER
  • Use production credentials
  • Allow outbound to prod from decoy
  • Store real PII in lures
  • Disable audit for any action
🔒
Isolation Guarantees
Hard technical controls — not policy only
ENFORCED
Network Air-Gap (no prod route)
Decoy VLANs have no route to production subnets. Verified by continuous probe.
Egress Deny-by-Default
Only allowlisted analysis/sinkhole destinations. All other outbound dropped + logged.
Namespace + cgroup isolation
Each honeypot in dedicated network + PID + mount namespace. Resource limits enforced.
No shared secrets with production
Honeytokens only. Production secrets never injected into decoy environment.
DNS Sinkhole mandatory for C2
Known C2 domains redirected to analysis node. Unknown domains logged + blocked.
🏷
Honeytoken Policy
Business + security rules for lures
ZLATÉ PRAVIDLO: Žádný honeytoken nesmí být platný produkční credential. Všechny lures jsou syntetické a sledovatelné.
Syntetické credentials only
Generované unikátní tokeny, nikdy reálné hesla/API klíče
Canary uniqueness
Každý token má unikátní ID pro attribution
No real PII in lures
Jména, e-maily, čísla karet jsou fake
Auto-expire after 90 dní
Staré tokeny se rotují a invalidují
